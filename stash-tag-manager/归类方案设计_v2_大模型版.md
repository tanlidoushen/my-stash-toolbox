# Stash 孤儿标签归类方案设计 v2 — 大模型版本

## 一、背景变更

原方案（v1）使用关键词匹配，存在大量歧义误判（如"黑人演员"被归到"发色"）。现改为**大模型语义分类**，利用 DeepSeek-V3.2 理解标签的真实语义，避免机械匹配的歧义问题。

## 二、输入数据

### 孤儿标签（1078 个）
每个标签包含：
- `id` — Stash 内部 ID
- `name` — 标签名称（中/英/日文混合）
- `aliases` — 别名数组
- `description` — 描述文本

### 29 个父标签（分类目录）
每个父标签包含：
- `id` / `name` — 如"性行为""服装""主题"等
- `children` — 该父标签下的所有子标签（含名称、别名、描述）

### 数据文件
- `all_tags.json` — 全部 3903 个标签
- `orphan_tags.json` — 1078 个孤儿标签
- `AI标签_未处理.json` — 46 个 AI 后缀标签（单独剥离，不参与分类）

## 三、归类流程

```
                          ┌─────────────────────┐
                          │  孤儿标签 1078 个    │
                          │  + 29 个父标签层级    │
                          └──────────┬──────────┘
                                     │
                          ┌──────────▼──────────┐
                          │  分批送入 DeepSeek-  │
                          │  V3.2 (硅基流动)     │
                          │  每批 50 个标签      │
                          └──────────┬──────────┘
                                     │
                          ┌──────────▼──────────┐
                          │  LLM 判断每个标签：    │
                          │  1. 归属哪个父标签    │
                          │  2. 匹配现有子标签     │
                          │     (合并别名) 还是   │
                          │     新建子标签        │
                          │  3. 无法归类的说明原因 │
                          └──────────┬──────────┘
                                     │
                          ┌──────────▼──────────┐
                          │  合并结果、去重       │
                          │  输出最终归类方案     │
                          └──────────┬──────────┘
                                     │
                          ┌──────────▼──────────┐
                          │  人工审核 → 批量写入  │
                          │  Stash GraphQL API   │
                          └─────────────────────┘
```

### Prompt 设计

每批给 LLM 发送：
1. **系统指令**：定义任务、输出格式、分类规则
2. **上下文**：29 个父标签及其子标签的结构化数据
3. **待分类标签**：50 个孤儿标签的详细信息

### 操作类型（action）
| 值 | 含义 |
|----|------|
| `merge_alias` | 合并到现有子标签的别名 |
| `new_child` | 在父标签下新建子标签 |
| `unsure` | 无法确定，需人工判断 |

## 六、成本估算

每批 50 个标签，约 22 批。每批：
- 输入：约 2000 tokens（上下文）+ 2000 tokens（标签数据）= 4000 tokens
- 输出：约 1500 tokens（JSON 结果）
- 每批成本：4000 × ¥4/M + 1500 × ¥6/M = ¥0.025
- **总成本：约 ¥0.55**（非常便宜）

## 七、执行步骤

1. 读取孤儿标签数据，分批次
2. 每批构造 prompt，调用 DeepSeek-V3.2
3. 解析 JSON 结果，合并所有批次
4. 输出归类方案（人工审核用）
5. 人工确认后，批量写入 Stash
