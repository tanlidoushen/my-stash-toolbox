# Stash Tag 孤儿标签归类方案设计

## 一、背景

Stash 实例现有 **3903 个标签**，其中：
- **29 个顶级父标签**（分类目录，如「性行为」「服装」「主题」「群戏组合」等）
- **2796 个标签有归属**（挂在这 29 个目录下）
- **1078 个孤儿标签**（无父无子，需要归类入库）

## 二、归类流程

```
孤儿标签 1078 个
    │
    ├─ 1️⃣ 语义分组 → 按名称/别名/描述的意思相近的归为一组
    │
    ├─ 2️⃣ 匹配父标签 → 每组匹配到 29 个顶级父标签中最合适的
    │
    ├─ 3️⃣ 匹配子标签 → 在每个父标签的下级标签中，检查名称/别名是否有语义重叠
    │                     （判断是**合并到现有子标签**还是**新建子标签**）
    │
    └─ 4️⃣ 输出结果
         ├─ A. 归类成功 → 写明归属路径（父标签 → 子标签）
         └─ B. 无法归类 → 单独列出，待讨论
```

## 五、匹配规则

### 第一步：孤儿标签分组

按语义分组，而非简单按首字母/前缀。匹配依据：

1. **名称相似度**（如 `3P, 4P` ≈ `3P/4P`）
2. **别名交集**（检查别名是否有共同元素）
3. **描述关键词**（如果描述中包含父标签的关键词）
4. **英文/中文互译对应**（如 `新娘·年轻妻子` = `Bride, Young Wife`）
5. **后缀/前缀模式**（如 `_AI` 后缀、`AV OPEN` 前缀）

### 第二步：匹配父标签

对每组，计算与 29 个父标签的语义匹配度：

| 匹配条件 | 权重 |
|---------|------|
| 名称直接包含父标签关键词 | 高 |
| 别名与父标签别名有交集 | 高 |
| 描述提及父标签范畴 | 中 |
| 与父标签下的子标签同族 | 中 |
| 仅通过联想匹配 | 低 |

### 第三步：匹配子标签（合并 or 新建）

在父标签的子标签中检查：

1. **名称完全相同** → 直接合并为别名（说明孤儿标签是冗余的）
2. **名称语义相同**（如 `新娘·年轻妻子` vs `Bride, Young Wife`）→ 合并为别名
3. **别名有重叠** → 合并为别名
4. **语义相近但现有子标签未覆盖** → 判断是否**新建子标签**

```

```

## 六、技术实现

### 匹配算法建议

```
1. 分词：对孤儿标签名和别名做中文分词 + 英文 tokenize
2. 关联度计算：
   - 检查孤儿标签名/别名是否出现在父标签或其子标签的别名中
   - 对每个孤儿标签，扫描所有父标签子标签的别名集合
   - 交集越大，匹配度越高
3. 相似度阈值：
   - 别名完全包含 → 直接合并
   - 名称模糊匹配（Jaccard 相似度 > 0.3）→ 建议合并
   - 无匹配 → 列为未归类
```

### 输出文件

- `归类方案设计.md` — 此文档，人工审核后确认
- `归类结果.json` — 程序自动生成的匹配结果（确认后输出）
- `未归类标签.txt` — 无法匹配的孤儿标签清单
